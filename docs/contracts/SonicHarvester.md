# SonicHarvester.sol Detailed Breakdown

## Purpose and Function

`SonicHarvester.sol` is a sophisticated and centralized smart contract designed to automate the collection, processing, and distribution of rewards generated by multiple, potentially diverse, yield-generating strategies. Its primary objective is to consolidate various reward tokens earned by these strategies into a single, predefined `liquidityAsset` (e.g., WETH, USDC) and then transfer this unified asset to a designated `rewardRecipient`.

The operational lifecycle of the `SonicHarvester` involves several key stages:

1.  **Reward Collection:** The harvester interacts with a list of whitelisted "strategy" contracts (which must conform to the `IHarvestable` interface). It calls a `collectRewards()` function on each of these strategies, prompting them to transfer their accrued reward tokens to the `SonicHarvester` contract.
2.  **Token Swapping:** Since strategies can yield rewards in various ERC20 tokens, the harvester swaps these diverse tokens into the common `liquidityAsset`. The initial implementation supports swapping via the Magpie DEX aggregator (`IMagpieRouter`). The specific parameters for the swap, including potentially signed data for the aggregator, are provided when initiating the swap.
3.  **Slippage Protection:** To safeguard against unfavorable market conditions or price manipulation during swaps, the `SonicHarvester` can be configured with a `priceProvider` (an `IOracle` compliant contract) and an `allowedSlippageBps` (basis points). After a swap, it compares the actual amount of `liquidityAsset` received against an expected amount calculated from the oracle's price for the input reward token, adjusted for the allowed slippage. If the received amount is below this threshold, the transaction can be reverted.
4.  **Distribution:** Once reward tokens are successfully collected and swapped into the `liquidityAsset` (and slippage checks pass), the resulting `liquidityAsset` is transferred to a pre-configured `rewardRecipient`. This recipient could be an Automated Redemption Module (ARM) to bolster its reserves, a protocol treasury, or a "dripper" contract designed for gradual reward distribution.

The contract is `Initializable`, making it suitable for deployment behind an upgradeable proxy. It also inherits from `OwnableOperable.sol`, which provides a two-tiered access control system: an `Owner` for critical configuration and an `Operator` for executing operational tasks like initiating swaps.

## Key State Variables & Functions

### Immutable State Variables
*   `liquidityAsset (address)`: The ERC20 token address that all collected reward tokens will be converted into. This address is set in the constructor and cannot be changed. The contract requires this token to have 18 decimals.

### Storage State Variables
*   `supportedStrategies (mapping(address => bool))`: A mapping that acts as a whitelist for strategy contracts. Only strategies marked as `true` can have their rewards collected by this harvester.
*   `priceProvider (address)`: The address of an external oracle contract (implementing `IOracle`) used to fetch reference prices for reward tokens. These prices are used for slippage validation during swaps. If set to `address(0)`, oracle-based slippage checks are skipped.
*   `allowedSlippageBps (uint256)`: The maximum allowed slippage for token swaps, expressed in basis points (1 bps = 0.01%). For example, a value of 300 means a 3% slippage tolerance. The maximum configurable value is 1000 bps (10%).
*   `rewardRecipient (address)`: The designated address that will receive the `liquidityAsset` after reward collection and successful swapping.
*   `magpieRouter (address)`: The address of the Magpie DEX aggregator's router contract, used for executing token swaps.

### Enums
*   `SwapPlatform { Magpie }`: An enumeration to specify the DEX aggregator platform to be used for swaps. Currently, only `Magpie` is supported.

### Events
*   `SupportedStrategyUpdate(address strategy, bool isSupported)`: Emitted when a strategy's support status is updated.
*   `RewardTokenSwapped(address indexed rewardToken, address indexed swappedInto, SwapPlatform swapPlatform, uint256 amountIn, uint256 amountOut)`: Emitted after a reward token is successfully swapped into the `liquidityAsset`.
*   `RewardsCollected(address[] indexed strategy, address[][] rewardTokens, uint256[][] amounts)`: Emitted after rewards are collected from one or more strategies.
*   `RewardRecipientUpdated(address rewardRecipient)`: Emitted when the `rewardRecipient` address is changed.
*   `AllowedSlippageUpdated(uint256 allowedSlippageBps)`: Emitted when `allowedSlippageBps` is updated.
*   `PriceProviderUpdated(address priceProvider)`: Emitted when the `priceProvider` address is changed.
*   `MagpieRouterUpdated(address router)`: Emitted when the `magpieRouter` address is changed.

### Custom Errors
*   `SlippageError(uint256 actualBalance, uint256 minExpected)`: Thrown if the amount received from a swap is less than the minimum expected amount after accounting for allowed slippage based on the oracle price.
*   `BalanceMismatchAfterSwap(uint256 actualBalance, uint256 minExpected)`: Thrown if the contract's balance of `liquidityAsset` after a swap does not correctly reflect the amount reported by the swap function.
*   And others like `InvalidSwapPlatform`, `UnsupportedStrategy`, `InvalidSwapRecipient`, `EmptyLiquidityAsset`, etc., for various input validations.

### Constructor
*   `constructor(address _liquidityAsset)`: Initializes the contract by setting the immutable `liquidityAsset` address. It includes checks to ensure `_liquidityAsset` is not `address(0)` and that it has 18 decimals (verified using `IERC20Metadata`).

### Initializer
*   `initialize(address _priceProvider, uint256 _allowedSlippageBps, address _rewardRecipient, address _magpieRouter) external initializer onlyOwner`:
    *   Called once when deploying behind a proxy.
    *   Sets the initial operational parameters: `priceProvider`, `allowedSlippageBps`, `rewardRecipient`, and `magpieRouter` by calling their respective internal setters.
    *   Also implicitly initializes `OwnableOperable` as part of the `Initializable` setup.

### Core Logic Functions
*   `collect(address[] calldata _strategies) external returns (address[][] memory rewardTokens, uint256[][] memory amounts)`:
    *   This function can be called by any address (it is not restricted).
    *   It iterates through the array of `_strategies` addresses provided.
    *   For each strategy, it first checks if `supportedStrategies[strategy]` is `true`. If not, it reverts with `UnsupportedStrategy`.
    *   It then calls `IHarvestable(strategy).collectRewards()`. This external call prompts the strategy contract to transfer its accrued reward tokens to the `SonicHarvester` contract. The `collectRewards` function is expected to return an array of reward token addresses and an array of corresponding amounts collected.
    *   Emits a `RewardsCollected` event with the details of all rewards collected from all strategies.
*   `swap(SwapPlatform swapPlatform, address fromAsset, uint256 fromAssetAmount, bytes calldata data) external onlyOperatorOrOwner returns (uint256 toAssetAmount)`:
    *   This function can only be called by the `Operator` or `Owner`.
    *   `swapPlatform`: Specifies the DEX aggregator to use (currently only `SwapPlatform.Magpie`).
    *   `fromAsset`: The address of the collected reward token that needs to be swapped.
    *   `fromAssetAmount`: The amount of `fromAsset` to be swapped.
    *   `data`: Platform-specific encoded data for the swap, e.g., for Magpie, this includes the swap route, signature, and other parameters.
    *   **Execution Flow:**
        1.  Records the `liquidityAsset` balance before the swap.
        2.  Calls the internal `_doSwap` function to perform the actual swap.
        3.  Verifies that the increase in the harvester's `liquidityAsset` balance matches the `toAssetAmount` returned by `_doSwap`. Reverts with `BalanceMismatchAfterSwap` if not.
        4.  Emits `RewardTokenSwapped`.
        5.  **Slippage Check (if `priceProvider` is set):**
            *   Fetches the price of `fromAsset` using `IOracle(priceProvider).price(fromAsset)`. (This assumes the oracle prices `fromAsset` against the `liquidityAsset` or provides a normalized price).
            *   Calculates the `minExpected` amount of `liquidityAsset` based on the `oraclePrice`, `fromAssetAmount`, and `allowedSlippageBps`.
            *   If `toAssetAmount` is less than `minExpected`, it reverts with `SlippageError`.
        6.  Transfers the `toAssetAmount` of `liquidityAsset` to the `rewardRecipient` using `SafeERC20.safeTransfer`.
    *   Returns `toAssetAmount` (the amount of `liquidityAsset` obtained from the swap).
*   `_doSwap(SwapPlatform swapPlatform, address fromAsset, uint256 fromAssetAmount, bytes memory data) internal returns (uint256 toAssetAmount)`:
    *   An internal function that abstracts the swap execution logic for different platforms.
    *   **For `SwapPlatform.Magpie`:**
        *   It uses EVM assembly (`assembly { ... }`) to parse the `data` byte array. This is done to extract specific fields like the intended recipient of the swap output, the input/output token addresses, and the input amount from Magpie's proprietary data structure. This parsing validates that the swap is correctly configured to send assets to the harvester itself and uses the correct tokens and amounts.
        *   If validations pass, it approves the `magpieRouter` to spend `fromAssetAmount` of the `fromAsset` (reward token) from the `SonicHarvester`'s balance.
        *   It then calls `IMagpieRouter(magpieRouter).swapWithMagpieSignature(data)` to execute the swap.
        *   Returns the `toAssetAmount` (amount of `liquidityAsset` received) as reported by the Magpie router.
    *   If an unsupported `swapPlatform` is given, it reverts with `InvalidSwapPlatform`.

### Administrative Setter Functions
These functions are typically restricted to the `Owner` or `Operator` as defined by `OwnableOperable`.
*   `setPriceProvider(address _priceProvider) external onlyOwner`: Updates the `priceProvider` address.
*   `setAllowedSlippage(uint256 _allowedSlippageBps) external onlyOwner`: Updates `allowedSlippageBps`. Reverts if `_allowedSlippageBps > 1000`.
*   `setRewardRecipient(address _rewardRecipient) external onlyOwner`: Updates the `rewardRecipient` address. Reverts if `_rewardRecipient` is `address(0)`.
*   `setSupportedStrategy(address _strategyAddress, bool _isSupported) external onlyOwner`: Adds or removes a strategy from the `supportedStrategies` whitelist.
*   `setMagpieRouter(address _router) external onlyOwner`: Updates the `magpieRouter` address. Reverts if `_router` is `address(0)`.

### Inheritance
*   Inherits from `OwnableOperable.sol`: Provides `owner` and `operator` roles and associated modifiers (`onlyOwner`, `onlyOperatorOrOwner`).
*   Inherits from `Initializable.sol` (OpenZeppelin): Allows the contract to be deployed using a proxy pattern, with initialization logic in the `initialize` function.

## Interactions

*   **`IHarvestable` Strategies (External Contracts):**
    *   The `SonicHarvester.collect()` function calls `collectRewards()` on each contract address listed in `supportedStrategies`. These strategy contracts are expected to transfer their reward tokens to the `SonicHarvester`.
*   **`IMagpieRouter` (DEX Aggregator - via `magpieRouter` address):**
    *   During a `swap` operation (specifically within `_doSwap` for the `Magpie` platform), the `SonicHarvester` calls `swapWithMagpieSignature(data)` on the `magpieRouter` contract to exchange collected reward tokens for the `liquidityAsset`.
    *   Before this call, the `SonicHarvester` approves the `magpieRouter` to spend the specific reward token.
*   **`IOracle` (Price Oracle - via `priceProvider` address):**
    *   If a `priceProvider` is configured, the `SonicHarvester.swap()` function calls `price(fromAsset)` on this oracle to obtain a reference price for the token being swapped. This price is used to calculate the minimum acceptable output amount to protect against excessive slippage.
*   **`IERC20` / `IERC20Metadata` (Various Token Contracts):**
    *   **Reward Tokens:** The `SonicHarvester` receives various ERC20 reward tokens from the `IHarvestable` strategies. It then approves these tokens for spending by the `magpieRouter`.
    *   **`liquidityAsset`:** After a successful swap, the `SonicHarvester`'s balance of `liquidityAsset` increases. It then transfers this `liquidityAsset` to the `rewardRecipient`. The `IERC20Metadata` interface is used in the constructor to check the decimals of the `liquidityAsset`.
*   **`Owner` (Role from `OwnableOperable`):**
    *   The `Owner` is responsible for the overall configuration of the `SonicHarvester`. This includes calling `initialize` and subsequently using the various setter functions (`setPriceProvider`, `setAllowedSlippage`, `setRewardRecipient`, `setSupportedStrategy`, `setMagpieRouter`). The `Owner` can also manage the `Operator` role.
*   **`Operator` (Role from `OwnableOperable`):**
    *   The `Operator` (or `Owner`) is authorized to call the `swap()` function, which triggers the conversion of collected reward tokens into the `liquidityAsset` and their distribution.
*   **`RewardRecipient` (External Address):**
    *   This is the final destination for the `liquidityAsset` processed by the harvester. It's an address configured by the `Owner`.
*   **Proxy Deployment:**
    *   As an `Initializable` contract, `SonicHarvester` is designed to be deployed behind an upgradeable proxy (e.g., EIP-1967 compliant). This allows the harvester's logic to be updated without changing its operational address or losing its configuration.
